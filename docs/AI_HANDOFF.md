# 정진용의 인터랙티브 CV 개발 인수인계

이 문서는 정진용이 사이트를 직접 써 보고 정한 기준을 담는다. 이후 사용자가 결정을 바꾸면 최신 요청을 적용하고 이 문서도 함께 갱신한다. 파일별 구조와 화면 사양은 [디자인 시스템](DESIGN_SYSTEM.md)을 참고한다.

## 방문자가 만나야 할 사람

홈의 주인공은 AI 에이전트와 LLM을 공부하는 정진용이다. 방문자가 첫 화면에서 어떤 사람인지 파악하고, 관심이 가는 경험을 책에서 펼치거나 직접 질문할 수 있어야 한다. 정형화된 이력을 어떻게 탐색 가능한 경험으로 바꿨는지 보여 주는 것 자체도 이 CV의 목적이다.

- 학력·프로젝트·연구·대외활동을 함께 소개한다. 연합학습은 관련 논문과 FedOps 프로젝트 안에서 다룬다. 웹 개발은 활동 중 하나로 소개한다. 블로그는 개별 경험을 더 깊이 읽는 경로다.
- 홈과 챗봇의 이력은 [CV 데이터](../src/config/cv.ts)를 기준으로 맞춘다. A.ing 대표 작업은 동료들과 만든 **ResNet 교육자료**다. 잔차 연결, PyTorch 구현, CIFAR-10 실습으로 무엇을 가르쳤는지 보여 준다.
- 출판물을 추가할 때 제목, 저자 순서, 발표 역할, 게재·발행 상태를 구분한다. 논문에 적힌 연도를 연구 기간으로 옮기거나 팀 성과 전체를 개인 성과로 쓰지 않는다. [LinkedIn 출판물](https://www.linkedin.com/in/jinyongjeong/details/publications/)

## 책을 펼치는 경험과 시각 디자인

- 기존 서체와 용 아이콘, 따뜻한 종이색과 고전적인 책의 인상을 유지한다. 제목과 아이콘에 장식용 마침표를 붙이지 않는다. 단체의 고유 표기인 A.ing은 그대로 쓴다.
- 색과 글꼴은 [공통 토큰](../src/styles/tokens.css)을 사용한다. Primary는 짙은 갈색, Secondary는 세이지 그린, 강조색은 브론즈다. 새 화면에서도 이 토큰을 공유한다.
- 기록집의 네 장은 **Education · Projects · Research · Activities**다. 독자가 마우스로 페이지를 잡아 넘기거나 터치로 밀 수 있어야 한다. 화살표와 키보드 조작도 유지한다. 긴 문장과 제목은 좁은 화면에서도 책 영역 안에서 끝까지 읽을 수 있어야 한다. [기록집 컴포넌트](../src/components/RecordDesk.astro)
- 새 인터랙션은 방문자가 하는 행동과 그 결과부터 설계한다. 책장을 당겼을 때 종이가 따라오고 손을 놓으면 다음 기록이 드러나는 식이다. 장식용 바, Ctrl+K 명령창, CV 인쇄·PDF 버튼은 이전 피드백에서 제외했다.
- 전면 개편 당시 사용자는 지정한 갤러리 안에서 사례 100개를 먼저 조사하고 각각의 동작을 분석해 달라고 했다. 다시 전면 개편한다면 **입력 동작 → 화면 반응 → CV 탐색에 적용할 점**을 기준으로 검토한다. 당시 결과물은 원래 작업공간의 `outputs/interactive-cv-references-100.html`과 같은 이름의 JSON에 있다. 별도 클론에는 포함되지 않는다. [Awwwards Web Interactive](https://www.awwwards.com/websites/web-interactive/) · [GDWEB 실험적 웹사이트 목록](https://www.gdweb.co.kr/sub/list.asp?Txt_fgbn=5&Txt_bcode4=051510001)

## 진용의 아바타와 대화

- CV 대화창에는 정진용의 아바타와 현재 읽는 페이지가 표시된다. 데스크톱에서는 패널을 접고 모바일에서는 용 아이콘으로 대화창을 연다.
- CV 패널은 공개 이력·사이트 질문에 답한다. 개인적인 대화는 패널 하단의 ‘진용과 일상 대화’ 링크로 여는 독립 문서 `/chat/`에서 진행한다. 기록집 질문은 CV 패널을 연다.
- `/chat/`은 정진용의 원래 말투 LoRA를 병합한 `wlsdyd5373/jjmethod` Qwen3-1.7B Q4_K_M을 사용한다. 한국어 채팅 프롬프트, 선택지 안에서 고르기, 관련 후속 문맥과 스트리밍을 지원한다. CV 답변은 공개 기록과 현재 페이지에서 즉시 구성한다. ‘AI로 핵심 문장 보기’에서 같은 1.7B가 답변에 있는 문장의 번호를 고르면 원문을 표시한다.
- 방문만으로 모델을 받지 않는다. 첫 생성 또는 CV 핵심 문장 요청 전 1.11GB 다운로드를 안내한다. 방문자가 중지하거나 메모리를 해제할 수 있다. 페이지 종류를 넘거나 새로고침할 때 모델 자원을 해제하며 다음 방문용 가중치나 대화를 저장하지 않는다.
- 생성 답변은 첫 텍스트부터 스트리밍한다. 인사와 공개 이력은 모델 준비 전후에 같은 답을 준다. 최근 논문은 개별 제목·저자 역할·발행 상태로, 최근 프로젝트는 공개 아카이브의 날짜와 작업 내용으로 답한다. 저장소 업데이트일과 프로젝트 수행일을 구분한다. 채용 이유·강점·단점에는 [페르소나 기록](../src/config/persona.ts)의 1인칭 답변을 사용한다.

| 방문자 질문 | 기대하는 동작 |
| --- | --- |
| “너 왜 뽑아야 돼?”, “당신을 뽑아야 하는 이유는?”, “진용을 왜 뽑아야 돼?” | 세 표현 모두 개인건강데이터 연구와 FedOps에서 한 일을 같은 답변과 출처로 설명한다. |
| “너는 뭘 잘해?”, “진용의 장점은?” | System 1의 실기기 검증과 ResNet 공동 교육자료에서 강점을 보여 준다. |
| “진용의 단점은?” | 공개한 자기평가가 없다는 사실을 말한다. 연구 단계로 성격이나 단점을 추측하지 않는다. |
| “뭐 하는 사람이야?” | 이름이나 프로젝트명을 다시 묻지 않고 전공과 현재 관심 분야를 소개한다. |
| “너 최근에 논문 뭐 썼어?” → “아니 뭔 말이야” → “너 뭐했냐고” | 최근 논문을 이름으로 소개한 뒤 첫 논문의 방법과 진용의 저자·발표 역할을 설명한다. |
| “아니 너 최근에 한 프로젝트가 뭐야?” → “좀 더 자세히 알려 줘” | 프로젝트 아카이브의 최근 기록을 고르고, 이어지는 답변에서 같은 작업의 구체적인 내용을 설명한다. |
| 글을 읽으며 “이 글 요약해 줘” → “그럼 단점은?” → “너의 단점은?” | 앞의 두 질문은 현재 글을 대상으로 삼고, 마지막 질문에서 사람으로 대상을 전환한다. “네가 만든 프로젝트의 장점”도 프로젝트에 대한 질문이다. |

## 수정하고 확인하는 순서

1. 로컬 실행은 `npm ci` 후 `npm run dev`다. 홈은 `http://localhost:4321/`, 대화창을 바로 여는 주소는 `http://localhost:4321/?ask=1`이다.
2. 관련 코드를 고친 뒤 `npm run check`, `node --test tests/*.test.mjs`, `npm run build`로 확인한다. 책이나 대화창을 바꿨다면 실제 Chrome의 데스크톱·모바일 너비에서 페이지 넘김, 내용 잘림, 대화창 열기·접기와 입력까지 직접 확인한다.
3. Chrome에서 홈과 `/chat/`에 접속할 때 모델·런타임 요청이 없는지 확인한다. CV 질문의 출처, 핵심 문장 선택, 일반 대화의 스트리밍, 종료·재진입과 모바일 입력을 검증한다.
4. 사용자가 로컬 확인을 요청하면 미리보기 URL을 제공한다. 공개 배포 요청을 받으면 GitHub Pages 워크플로 완료 후 [공개 사이트](https://jinyong-jeong.github.io/)에서도 변경한 동작을 확인한다.
